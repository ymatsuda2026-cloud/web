# 議事録 v2：要約待ちを Claude.ai で要約する

議事録アプリ v2 は、議事録を暗号化して GitHub に保管している。Claude.ai は暗号を開けないので、
Mac が「要約待ち」の文字起こしだけを Notion の作業DBへ一時的に書き出している。
このスキルは、その作業DBのページを要約して JSON を書き込み、状態を「要約済み」にする。
Mac が次の確認（5分おき）で回収・暗号化し、アプリに反映したあと、Notion のページは消える。

## 作業DB

- 名前：**議事録 要約作業**（ID：`ここに NOTION_DB_ID を入れる`）
- プロパティ：名前（タイトル）／ID（テキスト）／状態（セレクト：要約待ち・要約済み）／メモ（テキスト）
- ページ本文：先頭に「会議日時・長さ」、続いて文字起こし。行頭の `[m:ss]` は発言の時刻

## 手順

1. 作業DBを開き、状態が「要約待ち」のページを一覧にする（名前・会議日時）。
   - `notion-search` は状態で確実に絞り込めないので、DB を `notion-fetch` するか、データソースを状態でクエリする。
   - 0件なら「要約待ちはありません。Mac が書き出すまで数分かかることがあります」と伝えて終わる。
2. どれを要約するか聞く。指定が無ければ全部を要約する。
3. 1件ずつ、ページ本文（文字起こし）を読み、下の形式の JSON を作る。
4. そのページの末尾に、JSON を **1つの json コードブロック** として追加する。文字起こしは消さない・書き換えない。
5. 状態を「要約済み」にする。
6. 全部終わったら、要約した件数と、各会議の cardSummary を一覧で伝え、
   「Mac の次の確認（5分以内）でアプリに反映されます」と添える。

## 要約の形式（この JSON だけを書く。キーは英語のまま）

```json
{
  "cardSummary": "一覧に表示する100字程度の要約",
  "summary": "会議の目的と結論を3〜5文で",
  "agenda": [
    {
      "topic": "議題（論点）の見出し",
      "t": "その議題が始まった時刻 m:ss",
      "outcome": "その議題の結論。結論が出ていなければ「継続検討」など",
      "points": [{ "text": "話された経緯・論拠を1件1文で", "t": "その発言の時刻 m:ss" }]
    }
  ],
  "decisions": [{ "text": "決定事項", "t": "決まった時刻 m:ss" }],
  "todos": [{ "text": "やること", "owner": "担当（分からなければ空）", "due": "期限（分からなければ空）" }],
  "topics": ["未解決の論点や気になる点"],
  "model": "Claude.ai"
}
```

- agenda は必ず1つ以上。議題ごとに分け、points は「なぜそうなったか」が後から追える順に並べる。
- `t` は文字起こしの行頭にある時刻をそのまま使う（`1:12:05` のような時:分:秒も可）。分からなければ `""`。
- decisions / todos / topics は該当が無ければ空配列。
- 文字起こしに無いことを書き足さない。人名・数値は文字起こしの表記のまま。日本語で書く。

## うまくいかないとき

- Mac が要約を読み取れなかったページは、状態が「要約待ち」に戻り、メモに理由が入る。
  そのページは、末尾の古いコードブロックを消してから、形式どおりの JSON を書き直す。

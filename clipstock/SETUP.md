# 動画ナレッジ — セットアップ

議事録アプリ(`minutes`)と同じ作りです。ブラウザ → GAS → Notion の3段で、
GASを挟んでいるのは Notion API に CORS ヘッダーが無く、ブラウザから直接叩けないためです。

```
Mac mini の cron                  このアプリ
(process_videos.py)               (ブラウザ + GAS)
      │                                 │
  URL を拾う                       サマリ / マインドマップ
  yt-dlp でメタ情報                分野別要約 / 応用 / 活用アイデア
  youtube-transcript-api で本文     ↓
      ↓                            状態: 完了 → 要約済み
  状態: (空) → 完了
      └──────────── Notion 動画DB ───────┘
```

前半(文字起こしまで)は今の Python スクリプトのままです。このアプリは
状態が「完了」になったものを引き取って、後半のAI生成を担当します。

---

## 1. Notion のカラムを追加する

既にあるカラム: `動画タイトル` `URL` `サムネイル` `タグ` `状態` `要約` `マインドマップ` `作成日時`

足りないものを追加してください。名前は完全一致させること(`gas/Code.gs` の
`PROP_*` と突き合わせています)。

| カラム名 | 種類 | 用途 |
| --- | --- | --- |
| `分野別要約` | テキスト | 分野ごとの切り口 |
| `応用` | テキスト | ビジネスへの展開 |
| `活用アイデア` | テキスト | 面白い活用方法 |
| `メモ` | テキスト | 手書きメモ(AIは触らない) |
| `要約モデル` | テキスト | 生成に使ったモデル名 |
| `要約日時` | 日付 | 生成時刻。鮮度の判定に使う |
| `原文文字数` | 数値 | 文字起こしの長さのキャッシュ |
| `公開` | チェックボックス | マインドマップタブに並べるかどうか |

マインドマップは自分で `公開` をONにしたものだけが並びます。逆にアイデアは既定で全部並び、
外したものだけ見出しの先頭に `[非公開]` が付きます(列は増やしません。後述)。

`状態` の選択肢に `除外` を足す必要はありません。Notion API は未登録の
選択肢名でも自動で作るため、アプリから初めて使ったときに増えます。

### web記事DB

動画DBに加えて web記事DB も同じ一覧に読み込みます。カラム名はタイトル欄だけ
違い、残りは動画DBと共通です。

| 動画DB | web記事DB |
| --- | --- |
| `動画タイトル` | `タイトル` |
| `URL` `サムネイル` `タグ` `状態` `要約` | 同じ名前 |

- **状態が空欄のページは一覧に出ません**。下書きを混ぜないための割り切りです
- 詳細画面とAI生成も動画と同じように使えます。そのため上の表にある追加カラム
  (`分野別要約` `応用` `活用アイデア` `メモ` `要約モデル` `要約日時` `原文文字数` `公開`)は
  web記事DB側にも同じ名前で作ってください。無いカラムに書き込もうとすると
  Notion がエラーを返します
- 一覧の上部に「動画 / Web」のチップが出、どちらかだけに絞れます
  (両方に件数があるときだけ表示)。カードには Web バッジが付きます

### 2000字の上限について

Notion のテキストプロパティは「1つの rich_text オブジェクトあたり2000字」が
上限です。配列は100要素まで持てるので、`Code.gs` の `richTextProp_()` は
2000字ごとに分割して詰めています。実質20万字まで入るので、以前のように
マインドマップを1800字に削る必要はありません。

### 保存フォーマット

`分野別要約` `応用` `活用アイデア` は、Notion上でそのまま読める形にしています。

```
## 技術
Attentionの計算量が主題になっている
- 全語対全語で類似度を取る
- 計算量は系列長の二乗
## 経営
導入コストの話
- GPU確保が前提になる
```

`## ` が項目名、次の行が説明、`- ` が箇条書きです。JSONにしないのは、
アプリを開かずにNotionで読めることを優先したからです。手で直すときも
この形を崩さなければアプリ側で正しく読めます。
応用と活用はアイデア1件ごとにアイデアタブへ出すかを切り替えられます。外したものは
見出しが `## [非公開] 営業フローの再設計` の形になります。列を増やさないのは、
アイデアは本文の中に何件も並んでいて、Notionの列では1件ずつ持てないためです。
番号で覚えると作り直しや並べ替えでずれるので、見出し自身に印を置いています。
`マインドマップ` は markmap 用の Markdown です(`#` が中心、`##` が大項目、`-` が枝)。
旧スキルがHTMLを書き込んだページは、`<` で始まる値として検出して
そのまま iframe で表示するので、作り直さなくても読めます。

枝に引いたマーカーは、他のタブと同じ `<m1>…</m1>` の形でその行のラベルに
埋め込まれます(`- <m1>要点</m1> [12:34]`)。座標を別に持たないので、
あとから Markdown を直しても位置がずれません。

## 2. GAS を用意する

`gas/Code.gs` を Apps Script プロジェクトに貼り、スクリプトプロパティを設定します。

| キー | 値 |
| --- | --- |
| `NOTION_TOKEN` | Notion インテグレーションのシークレット(動画DB側) |
| `WEB_NOTION_TOKEN` | web記事DBを別の統合に接続しているときのシークレット(未設定なら `NOTION_TOKEN`) |
| `ACCESS_TOKEN` | 自分で決める共有トークン。アプリ側の設定と同じ値にする |
| `code` | 権限コードの対応表 JSON 例: `{"dfkjnga":"xYz"}` |
| `VIDEO_DB_ID` | 動画DBのID(省略時は `Code.gs` の `DEFAULT_DB_ID`) |
| `WEB_DB_ID` | web記事DBのID(省略時は `DEFAULT_WEB_DB_ID`。空文字にするとwebを読まない) |

Notion 側で、そのインテグレーションを動画DBとweb記事DBに接続しておくこと(DBの
「…」→「接続」)。忘れると `object_not_found` になります。
動画とwebで統合を分けている場合は、`WEB_NOTION_TOKEN` を入れておけば
web記事のページへの保存だけそちらのトークンで行います。

デプロイ設定:

- 種類: ウェブアプリ
- 実行するユーザー: 自分
- アクセスできるユーザー: 全員

URLを知っていれば誰でも叩けるので、`ACCESS_TOKEN` のチェックが最後の防波堤です。
議事録アプリのGASに動画用の `case` を足して1つにまとめても動きます。

コードを使わない運用(自分だけで使う)でも支障ありません。明示的に
弾かれたコードを入れたときだけ読み取り専用になります。

## 3. アプリ側の設定

ES モジュールを使っているので、`index.html` は `file://` では動きません。
議事録アプリと同じように GitHub Pages に置くか、手元で確認したいときは
`python3 -m http.server` などで配信してください。
(データを入れずに画面だけ見たいときは `preview.html` を開いてください。
こちらは静的なので `file://` で開けます。)

配信できたら `index.html` を開き、右上の歯車から入力します。

- **GAS URL** — デプロイして得た `/exec` のURL
- **共有トークン** — スクリプトプロパティの `ACCESS_TOKEN` と同じ値
- **一覧JSONの場所** — 空欄なら同じリポジトリの `data/clipstock/` を見ます(次章)
- **AI接続** — baseUrl + APIキー + モデル名
- **AIへの指示(プロンプト)** — `data/clipstock/setting.json` の文面をここで上書きできます(後述)

AI接続は localStorage のキー `gemma-chat.settings` を議事録アプリ・gemma-chat と
共有しています。どれか1つで接続を足せば全部で使えます。

例(Gemini):

- baseUrl: `https://generativelanguage.googleapis.com/v1beta/openai`
- モデル: `gemini-2.5-flash`

## 4. 一覧JSONを用意する(表示を速くする)

一覧は開くたびにGAS経由でNotionを全件クエリしていたため、件数が増えるほど
最初の描画までが遅くなっていました。Mac mini 側で JSON を作っておき、
画面はそれを読むだけにします。**画像はこれまでどおりURL先から読みます**。

```
mac/scripts/video/build_clipstock_json.py
      ↓ Notion 動画DBとweb記事DBを全件クエリ
  index-video.json / index-web.json  一覧カード・検索・絞り込みに要る項目
  idea-video.json  / idea-web.json   応用と活用アイデアの本文(アイデア一覧が使う)
      ↓ git push
  data/clipstock/  ← アプリが読む
```

取り込み元ごとにNotionが別で、更新するジョブも別なのでファイルを分けています。
アプリは `-video` と `-web` を両方読んで1つの一覧にします。片方が無ければもう片方だけ出ます。

web記事DBのIDは環境変数 `WEB_DB_ID` で変えられます(空文字にすると読みません)。
web記事DBを別のNotion統合に接続しているときは `WEB_NOTION_TOKEN` にその統合の
トークンを入れてください(未設定なら `NOTION_TOKEN` を使います)。
web側が読めなくても動画ぶんは書き出します。

cron の例(1時間おき。文字起こしのバッチのあとに回すと噛み合います):

```cron
15 * * * * /usr/bin/python3 ~/tools/mac/scripts/video/build_clipstock_json.py --out ~/Claude/app/clipstock/data >> ~/clipstock_json.log 2>&1
25 * * * * ~/tools/mac/scripts/push/git_push_all.sh >> ~/git_push.log 2>&1
```

### 表示対象をURLで切り替える

「どの一覧JSONを読むか」と「どのNotionDBへ書き戻すか」は対になっているので、
`data/clipstock/spaces.json` にまとめて書き、その組み合わせに名前を付けます。
これをスペースと呼び、URLの `?space=<id>` で選びます。

```json
{
  "default": "all",
  "sources": {
    "video": { "label": "動画", "list": "index-video.json", "idea": "idea-video.json", "db": "video" },
    "web":   { "label": "Web",  "list": "index-web.json",   "idea": "idea-web.json",   "db": "web" }
  },
  "spaces": [
    { "id": "all",   "label": "すべて",  "sources": ["video", "web"] },
    { "id": "video", "label": "動画",    "sources": ["video"] },
    { "id": "web",   "label": "Web記事", "sources": ["web"] }
  ]
}
```

- `sources` … 取り込み元1つぶん。`list` / `idea` は `data/clipstock/` からの相対名、
  `db` は書き戻し先を選ぶキーで `gas/Code.gs` の `source` と一致させる
- `spaces` … 取り込み元の組み合わせ。画面上部のタブになる

```
index.html            → default のスペース(すべて)
index.html?space=web  → web記事だけ
```

### 「分類」カラムで分ける

Notion の `分類` カラムが**空のページ**が `index-video.json` / `index-web.json` に入ります。
分類が入っているページはそこには入らず、分類ごとのファイルに書き出されます。

```
分類が空      → index-video.json     / index-web.json
分類が「経営」→ index-経営-video.json / index-経営-web.json
              idea-経営-video.json  / idea-経営-web.json
```

分類が増えると `build_clipstock_json.py` が `spaces.json` に取り込み元とスペースを
`"auto": true` 付きで足します。ラベルや並び順を手で直したいときは `auto` を外してください。
以降そのスペースは自動更新の対象から外れます。分類が使われなくなると `auto` の項目だけ
取り下げられます(書き出し済みのJSONファイルは残るので、要らなければ手で消す)。

分類ごとのスペースは JSON が前提です。GAS 側は `分類` を見ないので、JSONが読めないときの
Notion 直読みへのフォールバックは「分類なし」のスペースでだけ働きます。

取り込み元を増やすときはコードではなく `spaces.json` に足します。
選択を localStorage ではなくURLに置いているのは、画面をリンクやブックマークで
配れるようにするためです。`spaces.json` が読めないときは、分割前と同じ
動画 / web の2つを使います。

`--out` に指定した場所と `mac/scripts/push/git_push_config.json` の
`clipstock-data` の `source_folder` を必ず一致させてください。ここがずれると、
古いJSONを配信し続けても誰も気づけません。

書き出しは一時ファイルを作ってから差し替えるので、cronの途中で読んでも
中途半端なJSONを掴むことはありません。

**JSONが読めないときは自動でNotionから直接読みます**。初回の準備前や、
手元で `python3 -m http.server` して確認しているだけのときも動きます。
トップバーの件数の横に `・JSON 9/10 07:15` と出ていればJSON経由です。

詳細画面(タブごとの本文)はこれまでどおりNotionから取ります。生成した直後の
内容がすぐ読めないと困るため、ここはJSON化していません。つまり
**一覧に出る情報だけが最大1時間ぶん古い**ことになります。

## 5. 使い方

### ライブラリ

サムネイルのグリッドです。カードの5つの点が、左から
サマリ / マインドマップ / 分野別 / 応用 / 活用 の生成状況です。
まだ開いていない動画は左端に細い線が付きます。

動画を開いて「すべて生成」を押すと、5段に分けて生成します。

1. サマリ・タグ(原文から)
2. マインドマップ(原文から)
3. 分野別要約(原文から)
4. 応用(1と3の結果から。原文は使わないので軽い)
5. 活用アイデア(同上)

タブと段を1対1にしてあるので、「この項目を作り直す」が本当にその項目だけを
作り直します。

1段目でタグを付けるとき、既にDBにあるタグの一覧をプロンプトに渡して
「まずこの中から選ぶ、どれも合わなければ新語を1件だけ」と縛っています。
何も縛らないと動画ごとに「AI」「生成AI」「人工知能」と語が増え、
溜まるほど絞り込みが効かなくなるためです。それでも残る表記ゆれ(全角/半角、
大小文字)は `src/lib/tags.js` が既存の綴りへ機械的に寄せ直します。
新しいタグが作られたときは画面上部に知らせが出ます。

段が終わるたびにNotionへ保存するので、途中で失敗しても手前の結果は残ります。
1段だけ作り直したいときは、そのタブを開いて「この項目を作り直す」。

トップバーの ✨ は、状態が「完了」のものをまとめて処理します。件数分だけ
APIを叩くので、寝ている間に回す使い方を想定しています。

### AIへの指示(プロンプト)を変える

5段ぶんの文面は `data/clipstock/setting.json` にあります。設定モーダルの「AIへの指示」から
選んで書き換えると、その端末だけの上書きとして保存されます(`setting.json` より
優先)。「既定に戻す」で上書きを外せます。

`{{NO_FENCE}}` のような `{{...}}` はアプリが埋める差し込み欄です。

| 欄 | 入る段 | 中身 |
| --- | --- | --- |
| `{{NO_FENCE}}` | 全段 | コードフェンスを付けさせない指示 |
| `{{TAG_RULE}}` | サマリ | 既存タグの一覧と「まずこの中から選ぶ」の縛り |
| `{{QUOTE_FIELD}}` | マインドマップ | 引用欄の定義。原文に時刻が無ければ空になる |
| `{{POINT_SHAPE}}` | 分野別 | points の形。時刻の有無で切り替わる |
| `{{QUOTE_RULE}}` | マインドマップ・分野別 | 引用の書き方の縛り。時刻が無ければ空になる |

消しても動きますが、タグの語彙が際限なく増えたり、再生リンクが付かなくなります。
出力のJSONの形(キー名)を変えると読み取りに失敗するので、そこは触らないでください。

### 動画を消す

詳細画面の「…」に2つあります。用途が違います。

- **一覧から除外する** — 状態を「除外」にするだけ。Notionのページは残ります。
  見たくないものを畳むための操作です。
- **Notionから削除する** — ページをNotionのゴミ箱へ移します。アプリからは戻せません
  (Notion側では30日間復元できます)。

削除しても一覧JSONは次のcronまで古いままなので、その場では手元の一覧からだけ
消えます。他の端末では次の更新までカードが残ります。

### マーカー

サマリ・分野別・応用・活用アイデアの本文をなぞると、色の選択が出ます。3色と消しゴム。
マーカーは `<m1>…</m1>` の形で本文の文字列そのものに埋め込まれ、既存のテキスト
プロパティにそのまま保存されるので、新しいカラムは要りません。座標を別に持たないため、
あとから本文を編集しても位置がずれて壊れることがありません。

「手で直す」ではマーカーのタグは見えません。保存時に、文言が変わらなかった範囲だけ
マーカーを引き継ぎます。書き換えた箇所のマーカーは外れます(ずれた位置に残って
誤爆するより、消える方が安全だという判断です)。

注意点が2つあります。**項目を作り直すとその項目のマーカーは消えます**
(元の文が無くなるため)。また**原文タブにはマーカーを引けません**。原文はページ本文に
あってプロパティではないので、対応するには別の仕組みが要ります。

### 動画の該当箇所へ飛ぶ

文字起こしに `[12:34]` の形で時刻が入っていると、分野別要約の各項目と原文タブに
再生ボタンが出て、動画のその位置から再生できます。時刻の入れ方は
`docs/process_videos_patch.md` を見てください。

時刻はAIに答えさせていません。各項目の根拠になった原文の引用をAIに出させ、
その引用を文字起こしから文字列として探して時刻を割り当てています。
見つからなければリンクを付けません。つまり**リンクが無い項目は、根拠を原文で
特定できなかったもの**です。もっともらしい時刻を作られて一度でも空振りすると、
以降どのリンクも信用できなくなるため、この作りにしています。

時刻の無い古い文字起こしでも、そのまま時刻なしで表示されます。

### 語彙の整理

トップバーのタグ印から開きます。タグの使われ方を棒で並べ、2回以下のものは
破線から下にまとめます。ここが伸びているほど、絞り込みが効かなくなっています。

統合の候補は共起から出しています。少ない方のタグが多い方といつも一緒に
付いているなら、別の観点ではなく言い換えの疑いが濃い、という判断です。
集計だけで出るのでAIは使っていません。実行するたびに提案が変わらないので、
前回見たものが次も同じ場所にあります。

「まとめる」を押すと、そのタグが付いた全ページをGAS側で置き換えます。
**この操作は元に戻せません**。「別物として残す」を押した組は次から出なくなり、
その記録は端末に残ります(Notionには書きません)。端末を変えると再び出ますが、
確認しなおすだけなので実害はありません。

### アイデア

`応用` と `活用アイデア` を動画をまたいで1本のフィードにした画面です。
動画単位で見ていると「何かに使えそう」で終わってしまうので、
アイデア側から入って元の動画に戻れるようにしています。
「掘り起こす」を押すとランダムに6件だけ出ます。

### チャット

動画1本に対しては、原文全文と要約のどちらをコンテキストにするか選べます。
横断チャットは要約を積むので、20件まで選べます。

## つまずきやすいところ

- **`Notion API 400: URL is not a property that exists`**
  MCP経由では `userDefined:URL` と表示されますが、REST API では `URL` です。
  `Code.gs` は `URL` を使っています。
- **`unauthorized`** — アプリの共有トークンとスクリプトプロパティの
  `ACCESS_TOKEN` が違います。
- **CORS エラーで必ず失敗する** — GAS呼び出しの Content-Type は
  `text/plain` のままにしてください。`application/json` にすると
  プリフライト(OPTIONS)が飛び、GASは応答できません。
- **マインドマップが出ない** — markmap を jsdelivr から読んでいます。
  読めない環境では、代わりにMarkdownがそのまま表示されます。
- **要約が途中で切れる** — モデルのコンテキスト長を超えています。原文は
  30,000字で切り詰めていますが、それでも足りない場合は
  `src/lib/generate.js` の `TRANSCRIPT_LIMIT` を下げてください。

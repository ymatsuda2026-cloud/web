# 動画ナレッジ — セットアップ

議事録アプリ(`minutes`)と同じ作りです。ブラウザ → GAS → Notion の3段で、
GASを挟んでいるのは Notion API に CORS ヘッダーが無く、ブラウザから直接叩けないためです。

```
Mac mini の cron                  このアプリ
(process_videos.py)               (ブラウザ + GAS)
      │                                 │
  URL を拾う                       サマリ / マインドマップ
  yt-dlp でメタ情報                分野別要約 / 応用 / 活用アイデア
  youtube-transcript-api で本文     ↓
      ↓                            状態: 完了 → 要約済み
  状態: (空) → 完了
      └──────────── Notion 動画DB ───────┘
```

前半(文字起こしまで)は今の Python スクリプトのままです。このアプリは
状態が「完了」になったものを引き取って、後半のAI生成を担当します。

---

## 1. Notion のカラムを追加する

既にあるカラム: `動画タイトル` `URL` `サムネイル` `タグ` `状態` `要約` `マインドマップ` `作成日時`

足りないものを追加してください。名前は完全一致させること(`gas/Code.gs` の
`PROP_*` と突き合わせています)。

| カラム名 | 種類 | 用途 |
| --- | --- | --- |
| `分野別要約` | テキスト | 分野ごとの切り口 |
| `応用` | テキスト | ビジネスへの展開 |
| `活用アイデア` | テキスト | 面白い活用方法 |
| `メモ` | テキスト | 手書きメモ(AIは触らない) |
| `要約モデル` | テキスト | 生成に使ったモデル名 |
| `要約日時` | 日付 | 生成時刻。鮮度の判定に使う |
| `原文文字数` | 数値 | 文字起こしの長さのキャッシュ |

`状態` の選択肢に `除外` を足す必要はありません。Notion API は未登録の
選択肢名でも自動で作るため、アプリから初めて使ったときに増えます。

### 2000字の上限について

Notion のテキストプロパティは「1つの rich_text オブジェクトあたり2000字」が
上限です。配列は100要素まで持てるので、`Code.gs` の `richTextProp_()` は
2000字ごとに分割して詰めています。実質20万字まで入るので、以前のように
マインドマップを1800字に削る必要はありません。

### 保存フォーマット

`分野別要約` `応用` `活用アイデア` は、Notion上でそのまま読める形にしています。

```
## 技術
Attentionの計算量が主題になっている
- 全語対全語で類似度を取る
- 計算量は系列長の二乗
## 経営
導入コストの話
- GPU確保が前提になる
```

`## ` が項目名、次の行が説明、`- ` が箇条書きです。JSONにしないのは、
アプリを開かずにNotionで読めることを優先したからです。手で直すときも
この形を崩さなければアプリ側で正しく読めます。

`マインドマップ` は markmap 用の Markdown です(`#` が中心、`##` が大項目、`-` が枝)。
旧スキルがHTMLを書き込んだページは、`<` で始まる値として検出して
そのまま iframe で表示するので、作り直さなくても読めます。

## 2. GAS を用意する

`gas/Code.gs` を Apps Script プロジェクトに貼り、スクリプトプロパティを設定します。

| キー | 値 |
| --- | --- |
| `NOTION_TOKEN` | Notion インテグレーションのシークレット |
| `ACCESS_TOKEN` | 自分で決める共有トークン。アプリ側の設定と同じ値にする |
| `code` | 権限コードの対応表 JSON 例: `{"dfkjnga":"xYz"}` |
| `VIDEO_DB_ID` | 動画DBのID(省略時は `Code.gs` の `DEFAULT_DB_ID`) |

Notion 側で、そのインテグレーションを動画DBに接続しておくこと(DBの
「…」→「接続」)。忘れると `object_not_found` になります。

デプロイ設定:

- 種類: ウェブアプリ
- 実行するユーザー: 自分
- アクセスできるユーザー: 全員

URLを知っていれば誰でも叩けるので、`ACCESS_TOKEN` のチェックが最後の防波堤です。
議事録アプリのGASに動画用の `case` を足して1つにまとめても動きます。

コードを使わない運用(自分だけで使う)でも支障ありません。明示的に
弾かれたコードを入れたときだけ読み取り専用になります。

## 3. アプリ側の設定

ES モジュールを使っているので、`index.html` は `file://` では動きません。
議事録アプリと同じように GitHub Pages に置くか、手元で確認したいときは
`python3 -m http.server` などで配信してください。
(データを入れずに画面だけ見たいときは `preview.html` を開いてください。
こちらは静的なので `file://` で開けます。)

配信できたら `index.html` を開き、右上の歯車から入力します。

- **GAS URL** — デプロイして得た `/exec` のURL
- **共有トークン** — スクリプトプロパティの `ACCESS_TOKEN` と同じ値
- **AI接続** — baseUrl + APIキー + モデル名

AI接続は localStorage のキー `gemma-chat.settings` を議事録アプリ・gemma-chat と
共有しています。どれか1つで接続を足せば全部で使えます。

例(Gemini):

- baseUrl: `https://generativelanguage.googleapis.com/v1beta/openai`
- モデル: `gemini-2.5-flash`

## 4. 使い方

### ライブラリ

サムネイルのグリッドです。カードの5つの点が、左から
サマリ / マインドマップ / 分野別 / 応用 / 活用 の生成状況です。
まだ開いていない動画は左端に細い線が付きます。

動画を開いて「すべて生成」を押すと、3段に分けて生成します。

1. サマリ・マインドマップ・タグ(原文から)
2. 分野別要約(原文から)
3. 応用と活用アイデア(1と2の結果から。原文は使わないので軽い)

1段目でタグを付けるとき、既にDBにあるタグの一覧をプロンプトに渡して
「まずこの中から選ぶ、どれも合わなければ新語を1件だけ」と縛っています。
何も縛らないと動画ごとに「AI」「生成AI」「人工知能」と語が増え、
溜まるほど絞り込みが効かなくなるためです。それでも残る表記ゆれ(全角/半角、
大小文字)は `src/lib/tags.js` が既存の綴りへ機械的に寄せ直します。
新しいタグが作られたときは画面上部に知らせが出ます。

段が終わるたびにNotionへ保存するので、途中で失敗しても手前の結果は残ります。
1段だけ作り直したいときは、そのタブを開いて「この項目を作り直す」。

トップバーの ✨ は、状態が「完了」のものをまとめて処理します。件数分だけ
APIを叩くので、寝ている間に回す使い方を想定しています。

### マーカー

サマリ・分野別・応用・活用アイデアの本文をなぞると、色の選択が出ます。3色と消しゴム。
マーカーは `<m1>…</m1>` の形で本文の文字列そのものに埋め込まれ、既存のテキスト
プロパティにそのまま保存されるので、新しいカラムは要りません。座標を別に持たないため、
あとから本文を編集しても位置がずれて壊れることがありません。

「手で直す」ではマーカーのタグは見えません。保存時に、文言が変わらなかった範囲だけ
マーカーを引き継ぎます。書き換えた箇所のマーカーは外れます(ずれた位置に残って
誤爆するより、消える方が安全だという判断です)。

注意点が2つあります。**項目を作り直すとその項目のマーカーは消えます**
(元の文が無くなるため)。また**原文タブにはマーカーを引けません**。原文はページ本文に
あってプロパティではないので、対応するには別の仕組みが要ります。

### 動画の該当箇所へ飛ぶ

文字起こしに `[12:34]` の形で時刻が入っていると、分野別要約の各項目と原文タブに
再生ボタンが出て、動画のその位置から再生できます。時刻の入れ方は
`docs/process_videos_patch.md` を見てください。

時刻はAIに答えさせていません。各項目の根拠になった原文の引用をAIに出させ、
その引用を文字起こしから文字列として探して時刻を割り当てています。
見つからなければリンクを付けません。つまり**リンクが無い項目は、根拠を原文で
特定できなかったもの**です。もっともらしい時刻を作られて一度でも空振りすると、
以降どのリンクも信用できなくなるため、この作りにしています。

時刻の無い古い文字起こしでも、そのまま時刻なしで表示されます。

### 語彙の整理

トップバーのタグ印から開きます。タグの使われ方を棒で並べ、2回以下のものは
破線から下にまとめます。ここが伸びているほど、絞り込みが効かなくなっています。

統合の候補は共起から出しています。少ない方のタグが多い方といつも一緒に
付いているなら、別の観点ではなく言い換えの疑いが濃い、という判断です。
集計だけで出るのでAIは使っていません。実行するたびに提案が変わらないので、
前回見たものが次も同じ場所にあります。

「まとめる」を押すと、そのタグが付いた全ページをGAS側で置き換えます。
**この操作は元に戻せません**。「別物として残す」を押した組は次から出なくなり、
その記録は端末に残ります(Notionには書きません)。端末を変えると再び出ますが、
確認しなおすだけなので実害はありません。

### アイデア

`応用` と `活用アイデア` を動画をまたいで1本のフィードにした画面です。
動画単位で見ていると「何かに使えそう」で終わってしまうので、
アイデア側から入って元の動画に戻れるようにしています。
「掘り起こす」を押すとランダムに6件だけ出ます。

### チャット

動画1本に対しては、原文全文と要約のどちらをコンテキストにするか選べます。
横断チャットは要約を積むので、20件まで選べます。

## つまずきやすいところ

- **`Notion API 400: URL is not a property that exists`**
  MCP経由では `userDefined:URL` と表示されますが、REST API では `URL` です。
  `Code.gs` は `URL` を使っています。
- **`unauthorized`** — アプリの共有トークンとスクリプトプロパティの
  `ACCESS_TOKEN` が違います。
- **CORS エラーで必ず失敗する** — GAS呼び出しの Content-Type は
  `text/plain` のままにしてください。`application/json` にすると
  プリフライト(OPTIONS)が飛び、GASは応答できません。
- **マインドマップが出ない** — markmap を jsdelivr から読んでいます。
  読めない環境では、代わりにMarkdownがそのまま表示されます。
- **要約が途中で切れる** — モデルのコンテキスト長を超えています。原文は
  30,000字で切り詰めていますが、それでも足りない場合は
  `src/lib/generate.js` の `TRANSCRIPT_LIMIT` を下げてください。
